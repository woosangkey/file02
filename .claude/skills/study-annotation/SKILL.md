# 스터디북 필기 도구 (study-annotation)

『천로역정 셀프 스터디북』 합본에서 아이패드 실기기 검증까지 마친 필기 도구를 다른 HTML 교재 아티팩트에 붙이는 방법.

- 완성본: `assets/notes.js`(스크립트, `<script>`로 감싸져 있음), `assets/notes.css`(스타일)
- 원본 적용 예: 천로역정/도구/combine.py가 합본을 만들 때 CSS는 `<style>` 끝에, JS는 페이지 스크립트 뒤에 붙인다.
- 두 번째 적용 예: 『법인 컨설팅 100문 100답』 웹북(`corp-book/web.py` + `web_template.html`) — 아래 "다른 구조에 맞추기"의 실제 사례.

## 1. 페이지가 갖춰야 할 구조

notes.js는 아래를 전제로 한다. 다른 교재면 이 이름들을 그 교재의 구조에 맞게 바꾼다 (파일 위쪽 상수와 선택자).

| 전제 | 쓰임 | 바꿀 곳 |
|---|---|---|
| `article.chap[id][data-title]` (장 단위) | 장별 저장 키 `ch-<id>`, 모아 보기 장 목록 | `arts`, `inArticle`, `data-title` |
| `section.page[id]` (`position:relative`) | 손글씨·형광펜 층(svg)이 덮는 단위, 저장 키 `ink-<장>-<단락>` | `sections()`, `sid()` |
| `BLOCKS` 선택자 | 문장 분할·형광펜 텍스트 수집 대상 | `var BLOCKS=` |
| `.qa > div` 안의 `.q` | "✎ 내 답 쓰기" 칸이 붙는 질문 | `renderAns()` |
| `.bar` | "필기" 버튼이 붙는 상단 바 | `document.querySelector('.bar')` |
| `chapshow` 커스텀 이벤트(detail=장 id) | 장이 바뀌어 보일 때 데이터 로드·층 생성 | 장 전환 코드에서 `document.dispatchEvent(new CustomEvent('chapshow',{detail:id}))` |
| 숨긴 장은 `data-off` 속성 | 지금 보이는 장에만 층을 만듦 | `arts.filter(...data-off...)` |
| `#chap` 장 선택 `<select>` | 모아 보기에서 누른 항목의 장으로 이동 | `jumpTo()`, 모아 보기 클릭 처리 |
| 색 토큰 `--paper --ink --muted --rule --guide --frame --plum --serif --sans` | 도구 창·내 답 칸 색 | notes.css |

장 구분이 없는 단일 문서면 `<article class="chap" id="c01" data-title="…">`로 본문 전체를 한 번 감싸면 된다.

**`sid()` 주의**: 원본은 단락 id가 `c01-s3`처럼 장 접두사를 가진다고 보고 `sec.id.split('-').slice(1)`을 쓴다. 단락 id에 `-`가 없으면(예: `q021`) 모든 단락이 `x`로 겹쳐 손글씨가 섞인다 → `sid()`를 `return sec.id;`로 바꾼다.

## 2. 붙이는 순서

1. notes.css 내용을 페이지 `<style>` 맨 끝에 넣는다.
2. 페이지 자체 스크립트 뒤에 notes.js(이미 `<script>…</script>`)를 넣는다.
3. 장 전환 코드에서 `chapshow` 이벤트를 보낸다.
4. Artifact 게시 때 `capabilities: {"db": {}, "user": {}}`를 선언한다 → 로그인한 사용자는 계정의 비공개 영역(`data/users/<id>/`)에 저장되어 기기 간 동기화. 안 되면 자동으로 그 기기 localStorage에만 저장.
   - 게시 전 `artifact-capabilities` 스킬을 불러와 현재 계약을 확인할 것.

## 3. 도구 동작 (사용자 설명용)

- **필기** 버튼 → 오른쪽 아래 도구 창. 설명 줄 없이 아이콘·색·굵기만.
- **형광펜**: 색(노랑 기억 · 분홍 찔림 · 하늘 약속 · 연두 질문)을 누르면 켜지고, 펜슬로 줄 위를 그으면 굵은 반투명 마커 획. 굵기 3단계. 위아래 흔들림을 강하게 잡아 줄 따라 반듯하게. (색 이름은 교재에 맞게 `COLORS`에서 바꾼다.)
- **형광펜 톡(문장 / 용어)**: 형광펜을 고른 채 글자 위를 펜슬로 **톡** 누르면(움직임 14단위 미만) 획 대신 텍스트에 칠한다. 도구 창의 `문장 | 용어` 버튼으로 고름(`ppnote-hm`에 기억).
  - 문장: 누른 문장 전체(`.sn` 조각 묶음)를 칠함.
  - 용어: 누른 낱말에서 조사를 떼고(뗀 말이 장 안에 더 자주 나올 때만 — "공제한도"→"공제한" 방지) 그 장의 같은 용어를 전부 칠함. 한 번에 칠한 것은 묶음 id `g`를 가져 되돌리기·지우기·다시 톡이 묶음 단위.
  - 이미 칠한 곳을 톡 → 지움. 끌면 지금처럼 마커 획.
  - 낱말 찾기는 `Range.getClientRects()`로 좌표를 비교한다(caret API 안 씀, 4절 1번).
- **만년필**: 펜촉 각도(-0.7rad)에 따라 굵기 변화 + 필압·속도 반영 + 손떨림 보정 + 시작/끝 가늘게 → 글씨가 정돈돼 보임. 먹색·남색·적갈색, 굵기 3단계.
- **볼펜**: 고른 굵기.
- **0.5초 멈추면 직선**: 긋다가 펜슬을 0.5초 멈추면 시작점부터 직선으로 바뀌고, 떼기 전까지 끝점을 움직일 수 있음(형광펜은 거의 수평이면 수평으로).
- **지우개**: 획 위를 문지르면 근처 획 삭제(반경 14 단위). 칠한 텍스트(`mark.hl`)도 누를 때뿐 아니라 **문지르는 동안** 지나가면 지운다(처음 누른 자리만 보던 탓에 iPad에서 "안 지워짐"이었음).
- **되돌리기**, **펜슬로만 쓰기**(터치 기기 기본 켬: 손가락은 스크롤).
- **내 답**: 질문마다 칸, 0.7초 멈추면 저장, 필기를 꺼도 쓴 답은 보임.
- **도구 창 옮기기**: 손잡이(점 6개)를 끌어 옮김. 놓으면 가장 가까운 화면 끝(왼쪽·오른쪽·위·아래)에 붙고, 위치는 기억됨(`ppnote-dock2`). 화면 밖으로 안 나감.
- **도구 창 모양 자동 전환**: 왼쪽·오른쪽 끝에 붙으면 세로(도구 한 줄 + 색·굵기 한 줄, 두 열), 위·아래 끝에 붙으면 가로. 위에 붙을 때는 상단 `.bar` 아래에 놓인다. 모양이 바뀌면 손을 놓은 자리 중심에 다시 맞춘다.
- **글자 크기 가− / 100% / 가+**: 상단 `.bar`에 늘 보이는 버튼(필기를 안 켜도 됨, 가운데 %를 누르면 기본 크기)과 도구 창에 같은 버튼. 본문만 0.8~1.8배(`--rz`, CSS zoom, `ppnote-rz`에 저장). 크기를 바꿔도 화면 위쪽에 있던 단락 위치를 유지한다. 앱 전체를 손가락으로 확대하는 대신 쓰도록 안내.
- **모아 보기** (천로역정 합본에서는 사용자 요청으로 버튼을 뺌. 코드는 남아 있어 `data-a="gather"` 버튼을 다시 넣으면 살아남): 형광펜 획이 지나간 문장 + 내 답을 장별·색별로, 누르면 그 자리로 이동. 저장 위치 안내도 여기.

## 4. 아이패드에서 배운 것 (반드시 지킬 것)

실기기에서 여러 번 실패하고 찾은 원칙. 바꾸지 말 것.

1. **형광펜을 텍스트 선택·클릭에 기대지 말 것.** 아티팩트 iframe 안의 iPad Safari에서는 길게 눌러 선택, `selectionchange`, 일반 텍스트의 click, `caretRangeFromPoint` 기반 방식이 모두 실패했다. 펜과 같은 svg 덮개 층의 pointer 이벤트로 그리는 마커 획만 확실히 동작했다.
2. **펜슬 근접(호버) 자동 필기 방지**: pointermove에서 `pointerType!=='touch' && buttons===0`이면 즉시 획 종료, `pressure===0`인 펜 이벤트 무시.
3. **펜슬로만 쓰기**: 층에 `touch-action:auto`를 두고 touchstart에서 `touch.touchType==='stylus'`일 때만 `preventDefault()` → 펜슬은 그리고 손가락은 스크롤.
4. **저장소를 기다리지 말 것**: 화면 반영은 즉시(메모리+localStorage), 계정 db는 뒤에서. db get에는 4초 시간 제한. 응답 없는 db(동의 창 미응답 등) 때문에 기능이 멈췄던 적이 있다.
5. **도구 상태가 남지 않게**: pointerdown마다 `erasing=false`로 초기화, 지우개가 아닐 때 지우기 상태 무시(손 뗀 신호가 빠지면 다른 도구가 계속 지우기만 하던 버그).
6. `setPointerCapture`는 `try{}`로 감쌀 것.
7. **손글씨 좌표는 단락 폭 1000 기준으로 정규화**(viewBox `0 0 1000 H`) → 폭이 바뀌어도 비율 유지. 대신 줄바꿈이 크게 바뀌면 글줄과 어긋날 수 있음을 사용자에게 알린다.
8. **확대 대응**: 도구 창은 `visualViewport`(scale·offset)로 매번 위치를 다시 계산하고 `scale(1/scale)`로 크기를 되돌려 화면상 같은 크기·같은 모서리에 둔다. 단, 아티팩트는 앱 안 iframe이라 앱 전체 확대가 페이지에 전달되지 않을 수 있으므로 글자 크기 버튼을 함께 둔다.
9. iOS 캔버스 크기 제한 때문에 canvas가 아닌 SVG path로 그린다.
10. **진단용 표시는 게시본에 남기지 말 것.** 실기기 문제를 찾느라 도구 창에 진단 줄을 넣었다면 확인 후 반드시 지운다.
11. **같은 페이지에 자체 필기 코드를 따로 두지 말 것.** 선택(드래그) 기반 형광펜 팝업, 별도 손글씨 층 등을 함께 두면 iPad에서 이벤트가 엉키고 "작동 안 함"으로 보인다. notes.js 하나만 쓴다(법인 컨설팅 웹북에서 겪음).
12. **필기할 수 있는 곳은 모두 층 단위 안에 둘 것.** 장 첫머리(들어가기 글)가 `section` 밖에 있으면 svg 층이 없어 펜·지우개가 그곳에서만 안 된다. 법인 컨설팅 웹북은 소개 글을 `section.qsec.intro-sec`로 감싸고, 내 답 칸은 `:not(.intro-sec)`로 뺐다.

## 5. 검증 (게시 전 1회)

- 스크립트 문법: 합본에서 `<script>` 블록마다 `new Function(src)`(또는 `node --check`)로 확인.
- 헤드리스 크롬(`/opt/pw-browsers/chromium-*/chrome-linux/chrome --headless --dump-dom`, 또는 Playwright)에서 테스트 페이지에 `window.claude` 가짜(db get이 영원히 대기하는 버전 포함)를 넣고, svg 층에 `PointerEvent`(pointerType `'pen'`, buttons 1/0)를 보내 획 수를 확인. 대상 요소가 화면 안에 있도록 창 높이를 크게 잡을 것(`--window-size=1000,3000`).
- 실제 아이패드 확인은 할 수 없으므로 사용자에게 새로고침 후 시험을 요청한다.
